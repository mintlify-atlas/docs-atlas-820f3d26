---
title: "How Chromex handles credentials and API keys"
description: "Chromex never stores OAuth tokens or raw API keys in Chrome extension storage. Learn where credentials live and how sign-in works through the local bridge."
---

Chromex keeps credentials out of the Chrome extension entirely. The extension stores UI state; the local bridge handles anything that resembles a secret. This page explains exactly what is and is not stored, where it lives, and how sign-in works.

## What is never stored in Chrome extension storage

The following are never written to `chrome.storage` or any extension-accessible location:

- Raw OpenAI API keys
- OAuth tokens
- ChatGPT session tokens
- Any authentication secret

If you inspect the extension's storage in Chrome DevTools, you will find UI preferences, onboarding state, selected model, and optional connection configuration — nothing that could be used to authenticate against an AI service.

## Sign-in flows

### Codex OAuth / ChatGPT login

ChatGPT authentication is handled entirely by the local Codex app-server, not by the extension. When you sign in through the Chromex onboarding flow, the extension opens the Codex app-server login page. The resulting session token is persisted by Codex on your local machine, outside Chrome extension storage.

### API key login

An OpenAI API key is an optional local fallback. Chromex never uses it automatically without explicit user confirmation. When you provide an API key through the Chromex settings, the local bridge stores it in a per-user secret file on your machine — not in the Chrome extension.

The secret file is written with restrictive permissions (`0600` on Unix) so only your user account can read it:

```text
~/Library/Application Support/CodexSidepanel/secrets.json   (macOS)
~/.config/codex-sidepanel/secrets.json                       (Linux)
%LOCALAPPDATA%\CodexSidepanel\secrets.json                   (Windows)
```

The bridge reads this file on startup through `InMemoryBridgeSecrets` (`packages/bridge/src/secrets.ts`). The API key is held in memory and is never forwarded to the extension.

## What is stored in Chrome extension storage

`chrome.storage` holds only non-sensitive state:

| Stored item | Purpose |
|---|---|
| Theme and language preference | UI appearance |
| Selected model | Last-used model choice |
| Onboarding state | Whether setup is complete |
| Enabled skills | Which Codex skills are active |
| Connection overrides | Optional advanced runtime config |
| Profile templates | User-defined prompt profiles |

None of these items are authentication secrets.

## Chat history

Conversation history is **session-only by default**. When you close the side panel or navigate away, the current conversation is not persisted.

Persistent local chat history is opt-in. You can enable it in **Settings → Workspace**. When enabled, conversation data is stored locally on your machine by the bridge — not synced to any remote service and not stored in Chrome extension storage.

## How the local bridge protects secrets

The bridge applies two layers of protection to the secret file and any child processes it spawns:

1. **File permissions**: the secret file is written with mode `0600`, readable only by the owning user.
2. **Reduced environment allowlist**: native-host child processes and workspace hook commands receive a filtered copy of the environment. Unrelated shell secrets present in your terminal session are not inherited by bridge subprocesses.

Additionally, the diagnostics log system automatically redacts sensitive patterns before writing to disk. Keys matching patterns like `api_key`, `authorization`, `token`, `secret`, and `password` are replaced with `[redacted]`, and OpenAI key patterns (`sk-...`) and base64 image data are stripped from log entries.

## How to sign in

<Steps>
  <Step title="Open Chromex">
    Click the Chromex icon in the Chrome toolbar or open it from the side panel.
  </Step>
  <Step title="Follow onboarding">
    The onboarding flow detects whether the native bridge is running and whether you are signed in.
  </Step>
  <Step title="Sign in through the app-server login">
    Select **Sign in with ChatGPT** or **Use API key**. For ChatGPT login, you are directed to the Codex app-server login page. For API key login, you enter your key directly in the Chromex settings UI, and the bridge stores it locally.
  </Step>
  <Step title="Verify connection">
    Once signed in, the system status screen in onboarding confirms that the native host is connected and the Codex binary is detected.
  </Step>
</Steps>

<Tip>
To sign out or rotate your API key, go to **Settings → Account** and select **Clear API key**. The bridge deletes the secret file from disk.
</Tip>

For the full security architecture — including the runtime boundary, process isolation, and source-control defaults — see [Security overview](/security/overview).
</Note>
